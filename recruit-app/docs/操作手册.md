# 操作手册 · 猎聘候选人智能搜寻

> 本系统用**华联半导体自己的猎聘企业版账号**（`lpt.liepin.com`），按人才画像自动搜索匹配简历。
> ⚠️ 合规红线（系统代码已内置约束，操作时同样遵守）：
> - 仅使用本公司猎聘企业版账号，不借用他人账号
> - 低量限速，不批量高频抓取（系统已内置间隔与上限，**不要手动调小**）
> - 不抓取、不导出候选人手机/邮箱/微信等联系方式（导出已脱敏）
> - 通过猎聘平台站内功能触达候选人，不站外骚扰
>
> 请遵守猎聘平台规则与招聘数据使用规范。

---

## 0. 你需要准备的东西

| 项目 | 说明 |
|------|------|
| 猎聘企业版账号 | 能登录 `lpt.liepin.com` 的 HR/招聘账号 |
| 本机代理 | 科学上网工具（Clash/FlClash/V2Ray 等），猎聘访问需要 |
| 岗位要求 PDF | 《华联·技术1号位（研发负责人）人才画像》等 |
| 可选：LLM API | DeepSeek 等 OpenAI 兼容接口，用于 AI 深度评分（不配也能用规则打分） |

## 1. 启动系统

```bash
cd Desktop/hr/recruit-app

# 后端
source .venv/bin/activate        # Windows 下已在命令行激活则跳过
uvicorn backend.main:app --port 8000

# 前端（另开一个终端）
cd frontend
npm run dev                       # → http://localhost:5173
```

浏览器打开 **http://localhost:5173**。

> ⚠️ 若同时运行 BOM-AI（占用 8000/5173），按 README「端口冲突提示」改端口。

## 2. 设置页配置（最重要，一次配好）

进 **「设置」** 页，从上到下依次配置：

### 2.1 代理（WSL 下必填）
- 打开你的科学上网工具（Clash / FlClash / V2Ray），**确保 HTTP 端口已开**（FlClash 默认 `7890`）。
- 在设置页「代理」区填：
  - HTTP 代理：`http://127.0.0.1:7890`（换成你的实际端口）
  - HTTPS 代理：`http://127.0.0.1:7890`
- 说明：WSL 直连猎聘会被重置连接，必须让流量走 Windows 侧代理。TUN 模式开启后也可以不填（流量自动走代理），但建议填上，更稳。

### 2.2 浏览器（决定真实搜索能否跑起来）
推荐两种任选其一：
- **本机 Windows Chrome**：浏览器通道选 `chrome`，并在「浏览器可执行文件」填
  `/mnt/c/Program Files/Google/Chrome/Application/chrome.exe`
  （若装了 Edge 也可以：`/mnt/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`）
- **Playwright Chromium**：通道选 `chromium`，先装浏览器：
  ```bash
  cd Desktop/hr/recruit-app
  .venv/bin/playwright install chromium
  # 下载失败（网络受限）时用镜像：
  PLAYWRIGHT_DOWNLOAD_HOST=https://npmmirror.com/mirrors/playwright/ .venv/bin/playwright install chromium
  ```

无头模式建议保持默认：`browser_headless=true` 时无界面运行；如果你的 Windows 桌面愿意弹出真实 Chrome 窗口（更接近真人、风控更友好），可把无头改为 `false` 并配合通道 `chrome`。

### 2.3 猎聘 Cookie（登录态）
1. 在 Windows Chrome 里用**企业账号**登录 `https://lpt.liepin.com`（登录成功并停留在企业端页面）。
2. `F12` → **Application** → **Cookies** → 展开 `lpt.liepin.com` → 点右上角 Cookie 名第一行 → Ctrl+A 全选 → Ctrl+C 复制（得到 `xxx=yyy; aaa=bbb; ...` 的 Cookie 头）。
3. 回到设置页，Cookie 格式选 **header**，把复制内容粘进「猎聘 Cookie」框。
4. 点 **「测试连接」**。
   - 出现「会话有效，已登录企业版门户」→ 成功。
   - 出现风控/滑块提示 → 在本机真实浏览器完成验证后重新登录、重新复制 Cookie 再粘。
   - 出现「被重定向到登录页」→ Cookie 过期，重新登录后重粘。

> 三种格式都支持：`header`（上面这种）、`pairs`（每行 `name=value`）、`json`（EditThisCookie 导出）。**默认选 header 即可。**

### 2.4 搜索与触达（限速参数）
| 字段 | 默认 | 建议 |
|------|------|------|
| 搜索间隔 | 5 秒 | 保持默认或 ≥5 |
| 简历抓取间隔 | 15 秒 | ≥10 |
| 打招呼间隔 | 45 秒 | ≥30（猎聘对打招呼频次敏感）|
| 默认邀请岗位 ejobId | 空 | 在邀请页选岗位后自动带上 |
| 打招呼模板 | 空 | 例：`您好，我们是厦门华联半导体，正在招聘研发负责人，想邀请您投递…` |

### 2.5 AI 评分（可选）
- Base URL：如 `https://api.deepseek.com/v1`
- API Key、模型：`deepseek-chat`
- **不配置也能用**：AI 评分按钮会降级为规则打分兜底。

配置完点右下角 **「保存设置」**。

## 3. 画像页：从 PDF 生成画像

1. 进 **「人才画像」** 页。
2. 点「上传 PDF」选岗位要求 PDF（如《华联·技术1号位 V2.pdf》）。
3. 系统解析后会把结构化画像放进 JSON 编辑框，可手动微调（五维权重和为 100，硬性门槛里目标公司/年限很重要）。
4. 填画像名称，点保存。第一条会自动设为默认画像。

> 系统已内置默认种子画像（技术1号位 V2），不导入 PDF 也能直接开始搜索。

---

## 4. 搜索

进 **「智能搜索」** 页：

1. **新建搜索方案**：
   - 方案名称：如 `技术1号位 · 全量`
   - 关联画像：选上面保存的画像（留空用默认）
   - 搜索预设：**完整（公司+岗位+技术）** —— 会生成约 18 条关键词，覆盖目标公司/岗位词/技术词
   - 定时（小时）：先填 0（不自动）
2. 点该方案行的 **「运行」**。页面每 4 秒自动刷新。
   - 每条关键词依次在猎聘企业版搜索，命中卡片落库。
   - 搜索中可点 **「停止」** 中止本轮（已命中的已缓存，可下次断点续跑）。
3. 运行完成后，下方「候选人」表格出现候选人（绿色「新」= 本轮新发现）。

### 看候选人详情 / 重评
- 点候选人姓名 → **「候选人详情」** 页：显示卡片信息、初筛理由、五维评分。
- 点 **「抓取简历并重新评分」**：去猎聘抓取该候选人简历全文（系统自动脱敏，不存手机/邮箱），然后用规则重跑 hard_gate 一票否决 + 五维评分（原评分为 LLM 或规则覆盖刷新）。

### AI 深度评分
- 在智能搜索页，选中一个 run 后点 **「AI 深度评分」**：对当前 run 全部候选逐一调用 LLM 五维打分，覆盖规则分（LLM 未配置时自动降级规则分并标记）。

### 导出 Excel
- 进 **「运行历史」** 页 → 找到该 run → 点 **「导出 Excel」**。生成三个 sheet：候选人 / 评分明细 / 邀请。
- ⚠️ 导出内容不含手机/邮箱/微信（合规红线）。

## 5. 批量邀请（M6）

> ⚠️ **邀请接口需要一次性校准**（见下方「已知风险」第 1 条）。校准前批量邀请会明确报错，不会误发。

1. 进 **「批量邀请」** 页。
2. 选一个 **已完成** 的 run → 列表显示过 hard_gate（通过一票否决）的候选人，勾选要邀请的人。
3. **选择岗位**：点「拉取岗位」从猎聘企业版拉取当前在招岗位（如只有 1 个岗就选它）；若列表为空，可手动填岗位 `ejobId`（猎聘岗位链接 URL 里 `...?ejobId=xxxx`）。
4. 填（或确认）打招呼内容。
5. 点 **「批量邀请」**，系统按「打招呼间隔」限速串行发送，列表实时显示每条状态：
   - `pending` 排队中 / `sent` 已发送 / `failed` 失败（含错误原因）
   - 可 **停止** 批量、对单条失败记录点 **重试**。
6. 发送过程中不要去手动刷新猎聘页面（避免与系统抢会话）。

---

## 6. 定时搜索（M7）

在搜索方案编辑里把「定时（小时）」设为大于 0 的值（如 24 = 每天一轮），保存后系统会自动每隔该小时跑一轮搜索。规则：
- 若上一轮还在运行，自动跳过本轮（不叠加）。
- 新建/编辑搜索方案时**默认「启用」**；也可以关闭某个方案的自动运行。
- 已有 run 在跑时，本方案不会同时触发两轮。

> 定时搜索同样遵守限速；建议间隔 ≥ 4 小时，避免打搅猎聘平台。

## 已知风险与待校准项（重要）

1. **邀请 BFF 端点/请求体未实测校准**（`backend/liepin/codes.json` 中 `endpoints.invite` 与 `invite_body_template` 目前是 `PLACEHOLDER` 占位）。
   - 原因：真实 BFF 路径与请求体需要**账号+网络跑通一次**后才能用 DevTools 抓包确定，本项目环境无法代跑。
   - 校准方法：用企业账号在浏览器里手动对某候选人点一次「打招呼」→ DevTools → Network → 找到那条 POST 请求 → 把 URL 填进 `endpoints.invite`，把请求体 JSON 填进 `invite_body_template`（保留 `{resume_id}` / `{job_id}` / `{greet_message}` 三个占位符，系统会替换）。改完重启后端。
   - **未校准前，批量邀请按钮会明确报「尚未校准」错误，绝不会静默发错请求。**

2. **简历详情 BFF 响应形状待联调确认**（`resume_fields` 路径）。文本提取是防御性的（全字段拼文本），一般不影响匹配；若详情页结构化字段显示不全，用 DevTools 抓包对照 `codes.json` 的 `resume_fields` 校准路径即可。

3. **城市码为内置小表**（`search_planner.py` 的 `CITY_CODE_MAP`，厦门=750 等）。「地域」写成不可解析文本（如「不限」「厦门（可常驻）」）时会自动跳过城市筛选，不会发垃圾值；若需某城市未收录，在表里补 `城市: 码` 即可。

4. **Windows 浏览器路径依赖本机安装**：`chrome` 通道会自动探测本机 Chrome/Edge 路径；找不到时回退 Playwright Chromium。若探测失败，在设置页手动填浏览器可执行文件。

## 常见问题

| 现象 | 处理 |
|------|------|
| 测试连接「连接被重置 / 打开门户失败」 | 代理没配好或没开。检查 2.1 代理配置与代理软件端口 |
| 测试连接「被重定向到登录页」 | Cookie 过期。重新登录 `lpt.liepin.com` 后重粘 |
| 测试连接「风控/滑块」 | 在本机真实浏览器完成验证，重新登录后重粘 Cookie |
| 搜索 run 卡在 running | 点「停止」结束本轮；或等整批 deadline 自动超时（已命中已缓存） |
| AI 深度评分全报错 | LLM 未配置/Key 失效 → 会自动用规则分兜底，不影响使用 |
| 邀请报「尚未校准」 | 见「已知风险」第 1 条，校准 codes.json 后重启 |
